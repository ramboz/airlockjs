## Decision Options Considered

### Response-derived source checkpoint

Use the existing 051-09 source seams with owned synthetic inputs and a finite
first-party SDK double. Join the supplied records through the operator's shared
checker. This gives bounded causal source coverage while leaving real SDK and
operational proof open.

### Continue original-backed C

The original producer, manifest, three-digest handoff, assembler and real
operational inspector depend on the unavailable originals. Continuing that
assignment would not establish their custody. Keep its failure and requirements
as history rather than substituting synthetic inputs.

### Recover, relocate or recreate the originals

Reject this route. A different root, reconstructed evidence or a new marker
namespace does not establish historical authority or unused allowance.

## Recommended Decision

Subject to independent frame review and acceptance, select R1 inside existing
051-09. Use direct 1:1 supersession of ADR-0049 after acceptance, not a new
corpus migration, spec family, producer, assembler or runner. The proposed
[R1 source contract](../specs/051-adobe-integration-proving-ground/slice-09-focused-chamber-journey.md#replacement-r1-source-only-contract-and-completion-bar)
states the path and separate completion bar.

Extract the existing operator checks into `checkSupervisedJourneyCapture` in
the same module and call it from `runArm`. Join original request bytes,
admissions and body witnesses by identity; join the recorded response to the
returned proposition and applied host content; retain `checkStockWire` and
existing controls. The checker only checks relationships among supplied
records. Its bounded result must keep execution readiness and every actual,
provenance and compatibility claim false, including when called by `runArm`.

Withdraw new run admission and historical retry effects before READY, claims,
credentials, runtime imports, filesystem writes or other effects. A retry
refuses with `historical-retry-unqualified`; a new run returns a bounded
`source-unqualified` blocked result. No flag, root or fixture switch restores
admission. The real parent-alias filesystem race remains unqualified. Preserve
the existing consumed-job stop path and its independence from prior-pair
journals; do not claim stop or filesystem safety has been repaired.

Default tests must be hermetic. Historical qualification is explicitly
unavailable and remains opt-in, with missing original inputs failing when
selected. Synthetic fixtures cannot replace original roles or establish their
custody. The fixed SDK, adoption and governed wire, result and rendering gates
in ADR-0038, ADR-0039 and ADR-0045 survive. R1 grants no case, SDK slot,
resource, window, live authority, clock renewal or spending refund.

## Consequences

Owned inputs can exercise the real first-party source path without claiming
recovery of private evidence. The operational admission and retry routes are
withdrawn, not repaired or qualified. The checkpoint does not complete old C,
051-09 AC6/7, official Alloy compatibility, actual browser trust, live Adobe
dispatch, deployed-byte proof or downstream receipt.

cumulative spending and UNKNOWN treatment without refund, official SDK byte
provenance, independent stop ownership, current setup and exact owner approval.

Downstream reporting remains the nonblocking follow-up in ADR-0039.
