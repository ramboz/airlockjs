## Decision Options Considered

### Option A: Finish unattended execution qualification first
- **Pros:** Preserves the original operational bar without a proving exception.
- **Cons:** The existing facility's session-loss contract is unestablished;
  a native-service fallback would add implementation and qualification work.
  Retained for the wider campaign, not selected for this one pair.

### Option B: One owner-supervised functional proving pair
- **Pros:** Uses a visible foreground command and human-owned stop path;
  targets the actual integration rather than a new execution service.
- **Cons:** Requires the owner present throughout; cannot prove unattended
  loss survival or complete recursive descendant closure. Selected for
  the conditional supervised approach.

### Option C: Silently call detached mode or a borrowed case ready
- **Pros:** Appears to avoid another decision.
- **Cons:** Misstates qualification, changes case semantics or bypasses
  authority. Rejected.

## Recommended Decision

Use Option B as one narrowly labelled operational exception for051-09.
Acceptance records the design choice, not execution readiness. Before execution,
record the remaining routing decision and review the exact operator/stop/
accounting procedure; all admission conditions below remain mandatory.

### 1. Exception boundary and evidence label

For this pair only, propose replacing automatic caller-loss cleanup and
qualified descendant closure with an explicitly present external operator.
The operator starts the reviewed foreground command in a separate native
terminal, remains available, and owns the prepared stop-only procedure.
Chat activity, this planning approval or a file boolean is not readiness.
Before enabling anything, obtain a fresh explicit operator-ready observation.

The pair must remain labelled **owner-supervised proving evidence**. Never
turn a browser-close promise, window disappearance, PID list or human
observation into verified recursive closure. Missing native observations
remain UNKNOWN. No generic shutdown-survival or performance claim follows.
If the coding session disappears, the human-owned process/stop path remains
the planned custodian; this is an operational assignment, not a tested
unattended guarantee.

Keep runtime capability, consent, tenant, cookie, payload, safe-render and
trusted-click enforcement. No SDK fork, main-thread fallback, default product
change, production publication or new resource provisioning follows.

## Consequences

**Becomes easier:**
- Testing the real SDK/bridge/returned-render path without building another
  execution service first.
- Separating a functional proving result from reusable operational assurance.

**Becomes harder:**
- The owner must supervise the full pair and retain an independent stop path.
- Additional context/routing/accounting approvals are explicit; new private
  results cannot be promoted into the original campaign's ledger or criteria.

## Assumptions

- The owner can provide continuous foreground supervision and independently
  invoke the exact stop-only inverse. This is unverified until the run's
  operator-ready step; no background service substitutes for it.
- A small fixed foreground entry, egress expiry and bounded inverse can
  preserve the product controls and cumulative accounting without weakening
  frozen contracts or building another framework. The exact implementation/
  operational procedure is not yet authored or qualified.
- The new pair's preparation and stop fit the remaining existing administrative/
  cleanup budget. The35-call normal headroom is measured; actual plan cost is
  not. Additional contexts are now approved, but profile routing is not.

## Kill criteria

- Missing operator presence/stop access, a conflicting owned operation or
  inability to bound historical unknown work safely for this distinct pair.
- Missing context/routing/budget authority, current facts, all-ready preparation,
  source/served pins, reviewed accounting or exact operational approval.
- A need for unbounded requests, broader DOM/network authority, stock-case
  substitution, original-lock reset, relaxed product criteria or automatic retry.
- Inability to express the owned foreground/inverse procedure without another
  general runner/custody platform. Keep the proving path blocked instead.
