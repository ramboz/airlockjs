# ADR-0057: SDK-free Google local tests with manual helper cleanup

The local Google tests can leave Chrome helpers behind. Their cleanup stays
unknown/manual. Independent confinement and network-stop checks still have to
pass before a new finite run, and the parent must admit that exact packet.

## Decision Options Considered

| Option | Disposition |
|---|---|
| Require retrospective complete helper proof | Impossible for the old packet because identities were not retained. Keep that evidence gap visible without making it a circular prerequisite. |
| Introduce a new runner or custody framework | Outside this bounded owner choice. No runner, guardian, launchd job, supervisor or native broker is selected. |
| Treat root exit or manual cleanup as complete descendant cleanup | Rejected. Neither establishes that every helper exited or that case network work stopped. |

## Recommended Decision

Extend only the residual-helper acceptance to the existing SDK-free,
Google-only local test path.

1. Retain `descendant_cleanup: unknown_manual` and
   `complete_descendant_cleanup: false`. Do not infer complete descendants,
   agent-loss cleanup or profile deletion safety from root exit, manual
   cleanup, sampled absence or whole-command completion.
2. Independently establish confinement and network stop on the actual local
   path before admitting a new finite run. Identify its launcher/policy,
   allowed endpoints, receiver/fixture work and owned handles. Check stop and
   fixture release under that mechanism, including the implications of possible
   residual helpers. A flag, zero-arrival sample, root exit or unrelated
   cleanup surrogate cannot stand in for the property claimed. If a necessary
   condition fails, report that precise prerequisite and stop.
3. This decision does not import the native reference's proxy, H1/H2,
   retained-guard or slot rules into the nonproxy fixture. It does not grant a
   new guardian, reserved socket alias, process group, launcher, runner,
   launchd job, native component or supervisor programme.
4. Preserve known root ownership, owned worker/context/fixture closure,
   receiver evidence, strict recorder failures and independent whole-CLI
   completion. Unknown helper cleanup does not excuse a known root or owned
   resource that failed to close. Retain exact private recovery handles and
   profile dispositions. Do not scan unrelated processes, kill by name,
   touch an everyday Chrome instance or delete an unverified profile.
5. Before Chrome acquisition, complete this record's frame review and
   acceptance. Deliver the current source, exact browser metadata and
   executable/launcher/policy hashes, Node evidence, safety assessment and one
   concrete finite diagnostic plan to the parent for affirmative admission.
   The installed browser's plist is not a launched-version observation.
   No conditional proposal or earlier owner answer is that admission.
6. Preserve the existing packet ceilings: one browser root, at most eight
   fixture/context pairs and workers, 256 observed requests, 24 measurement
   attempts, 100 seconds of work and 120 seconds total including cleanup and
   publication. Use a fresh workspace-local profile. Ordinary tests stay
   browser-free. No retries, wider window or alternate confinement mechanism
   follow automatically.
7. Preserve every old artifact byte and keep old results tied to their source.
   The corrected source can justify a new falsifiable test without explaining
   the old abort. Missing bodies, failed requests, incomplete recordings or a
   failed actual safety check still stop that new packet. Recorder observations
   never supply runtime response data; opaque means HTTP unknown.
8. No vendor/official SDK, public Google request, cookie, credential, real
   destination or label, native/chamber case, original slot/authority mutation,
   production/core/frozen contract, Meta, deployment, account, billing,
   campaign, system trust or network-settings change is authorized.

## Consequences

Local source qualification can move forward without reconstructing the old
descendant set or building another runner. Possible helpers and unresolved
profile residue need an explicit private manual-recovery disposition.
The owner accepts this cleanup uncertainty; independent technical safety
qualification still has to supply its own evidence.

Full 059-01 remains READY_FOR_REVIEW/non-clearing and 059-15 remains IN_PROGRESS.
No native bytes, CORS, cookies, initialization, callbacks, calibrated
performance, Google receipt or full-conversion result follows from local
success.

## Kill criteria

- Confinement or network stop/fixture release cannot be established on the
  existing path without an unapproved mechanism or weaker guarantee.
- A known root/resource closure, no-external preflight or strict observer gate
  fails and is relabelled as accepted helper uncertainty.
- Unknown/manual cleanup is presented as complete helper or agent-loss proof.
- Execution starts without affirmative admission of the exact current packet,
  or exceeds its scope and finite ceilings.
