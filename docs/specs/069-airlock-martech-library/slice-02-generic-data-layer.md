## Slice 069-02 — Airlock's generic data layer, plus an opt-in `adobeDataLayer` migration proxy

**Goal:** The library's data layer is Airlock's own generic mechanism, with no ACDL and no `window.adobeDataLayer` by default: `push({ event, ...params })` and `getState(path)` in the shape of `contracts/push-api.md`, plus state pushes with no `event` key. `push` is O(1) in the state size (validate and append, no page code), the state folds lazily, and event pushes reach the library as the `sendAnalyticsEvent` arguments stock builds. A separate, explicit `installAdobeDataLayerProxy()` forwards ACDL-shaped object pushes into it for sites mid-migration; it is a migration aid, not a best practice. What ACDL gave that cannot cross the airlock is diagnosed, not emulated. The module is `adapters/eds/martech-datalayer.js`, adapter-level, with no `core/` change (ADR-0065 point 5's gap table). Why it is not core's `airlock.push` log: core drops pushes without `event`, projects last-write-per-type, and has no consumer surface; this module keeps core's envelope and shape and does not widen `core/`.

**DoR:**
- ✅ 064-21 done (the S10 differential and the stock ACDL 3.0.1 arm exist).
- ✅ ADR-0065 Accepted by the owner (2026-11-22; Option A is the owner's pick).

**Acceptance Criteria:**

1. **The generic mechanism, no global.** `createDataLayer({ onEvent, shouldProcessEvent, diagnose, airlock? })` returns `push` and `getState`. Creating it, pushing and reading state touch no `window.adobeDataLayer`, `window.alloy`, `__alloyNS` or `acdl` (hermetic global-proxy test), and a real-Chromium page that uses the library's data layer has `window.adobeDataLayer === undefined` and makes no `acdl.min.js` request. The envelope matches core: a push whose `event` is present must be a non-empty string; a malformed or non-object push is dropped with a `console.warn` and a `datalayer-bad-push` diagnostic, never thrown. A push with no `event` key is a state push (the gap with core, which drops it): it changes state and maps no event.
2. **Capture is O(1) and runs no page code.** `push(object)` validates a plain data object (own data properties only; a `Proxy`, an accessor or a non-plain prototype is dropped with `datalayer-bad-push`; a cyclic or over-deep object, past a documented depth bound, is dropped the same way, and so is one over a per-push node budget: shared references or a huge sparse array cannot make the walk explode), appends it to the queue and returns. It does no merge and no mapping: the cost depends on the pushed object's depth-bounded validation walk, not on the state size (hermetic: a visit counter shows the same count for a state of 10 keys and of 10,000). Hermetic tests: a getter on a pushed object is never invoked; a `Proxy`'s value-reading traps (`get`, `set`, `has`, `apply`, `defineProperty`, `deleteProperty`) are never hit, except that during one validation walk (`getOwnPropertyDescriptor` once per own key, and a nested Proxy's traps too) its `getPrototypeOf`, `ownKeys` and `getOwnPropertyDescriptor` traps may run, because no JS primitive tells a `Proxy` apart without them -> 069-04; a cycle does not overflow the stack. `shouldProcessEvent` and `onBeforeEventSend` are not called before `push` returns (hermetic). The drain runs in a separate task (`setTimeout(0)` or `scheduler.postTask`, not a microtask), tested with a task-boundary probe; it handles only what was queued when it started, so a hook that pushes cannot keep it running (tested). The drain and a direct `sendEvent` keep call order in the data layer's own queue (tested here); sharing one queue with the library's pre-boot queue -> 069-03 AC4's pre-boot replay.
3. **State equals ACDL's, folded lazily.** The state folds from the queue at `getState()`, at send when `includeDataLayerState` needs it, or in the drain, and is cached until the next push; the fold updates one state object in place, so a reference taken from `getState()` stays live and shows later pushes after the next read (hermetic: a reference taken before a push reflects it after the next read; a page that mutates the returned object outside `push` is unsupported and not detected, noted in the module header; also `push` does not fold; the reducer's visit counter is zero after a thousand pushes). `getState()` and `getState(path)` equal real ACDL 3.0.1's `getState()` on a corpus of pushes (nested objects, arrays, `null`, event items carrying data, the `event` and `eventInfo` keys, repeated keys), shown in real Chromium with both side by side. Every difference the corpus finds is fixed, or listed in the Findings as a dropped semantic with a diagnostic and a test of the difference. Against core's per-event projection (last write per type, `core/airlock.js`), the difference is named and tested: the data layer's `getState()` is a deep merge, core's projection stays unchanged. `getState` is a synchronous main-thread read of the live state by reference, per `contracts/push-api.md`. The reducer copies what it stores and skips `__proto__`, `constructor` and `prototype`, so no push can pollute `Object.prototype` (hermetic, revert-checked). The send-time merge hands the hook a copy (`structuredClone`), so a hook editing `payload.xdm.a.b` does not change the state (hermetic, matching stock's clone). The AC3 cost statement: `push` is O(1) and each state-carrying send is O(state size). What is measured here is push, fold, one state snapshot and the drain on the S10 state and a 100x copy (no Alloy merge, no network send); the Findings record it. The per-send snapshot and network cost is not measured here: 069-03 AC5 measures the state-carrying send with `includeDataLayerState`.
4. **Event mapping and timing.** A push with a non-empty string `event` produces, in the drain, `onEvent({ eventType: event, ...xdm }, data, configOverrides)` exactly as `aem-martech`'s listener builds its `sendAnalyticsEvent` arguments, taking only `event`, `xdm`, `data` and `configOverrides` (any other key, such as `renderDecisions`, `decisionScopes` or a consent field, is ignored; tested), without mutating the pushed payload. Order is preserved. The consumer attaches when the library's lazy phase starts and only when `analytics` is true, as stock registers its listener: events captured before attach are held and replayed in order, so none goes out before the page view. Difference from stock: the held queue is capped at `MAX_HELD_EVENTS` (200), oldest dropped with a `datalayer-held-overflow` diagnostic (dropped events still fold into state), and the cap also counts the library's direct `enqueue({ call })` entries, so a page-push flood can evict a library call; stock replays everything (handed to 069-03 AC4); with `analytics: false` state is kept and no event is mapped (both tested against the stock run in real Chromium). `shouldProcessEvent` returning false drops the event; one that throws drops it with a `hook-threw` diagnostic, matching the stock run (recorded in the real-Chromium arm). A data-layer event under pending or denied consent sends nothing until the seal allows it: the data layer only calls `onEvent`, and the handle's `sendEvent` and the seal decide (069-03 AC3).
5. **What ACDL gave that cannot cross, each with a diagnostic and a test (proxy surface).** Function push: never executed (asserted), `datalayer-function-push-dropped`. `addEventListener`, `removeEventListener`, `on`, `off`: present, register nothing, do not throw, `datalayer-listener-not-supported`. `adobeDataLayer:change` and `adobeDataLayer:event` notifications: not emitted. ACDL's cloning `getState`: the live state is returned (a test shows the live reference). Stock's eager-phase fallback (a shallow merge of non-event entries before ACDL loads): not reproduced; a real-Chromium test compares an eager-phase `sendEvent` body with the stock run's for a nested-state push, shows the difference (deep versus shallow, event items excluded versus included), owns it here and lists it in the Findings. `shouldProcessEvent` and `onBeforeEventSend` stay on the main thread and run in the drain (AC2).
6. **The opt-in proxy.** `installAdobeDataLayerProxy({ instanceName })` is the only code that touches `window.adobeDataLayer` (or the custom name). It drains the entries already on the array in order (object entries pushed into the data layer; function entries diagnosed), then patches `push` on the same array instance, so references the page took earlier keep working; the patched `push` still appends to the array and entries are not removed. With a custom `instanceName` the proxy writes exactly that name and `window.adobeDataLayer` is left as it was (stock's custom-name behavior), so AC9's allowlist is the one instance name. A foreign ACDL on the array at install (a `getState` and an `addEventListener` function, not ours) is not replaced: `datalayer-foreign-implementation`. One that loads later and replaces `push` is detected at the next drain, which stops forwarding and emits the same diagnostic, so no event is sent twice (hermetic stand-in that replaces `push` and replays the array). `alloy` and `__alloyNS` as the instance name are rejected with a plain Error. The proxy is never called by the library or by `initMartech` (hermetic here: a data layer used through `push`, `attach` and the drain leaves `window` untouched; the full `initMartech`, `martechEager` and `martechLazy` run leaving `window.adobeDataLayer` untouched -> 069-03 AC5), and its header and docs say it is a migration aid, not a best practice. Installing twice on the same name is a no-op, and a second name keeps the first proxy's drain-time detection; there is no uninstall (the spec does not require one).
7. **Blocks.** A `scanBlocks()` helper pushes `{ blocks: { [id]: data } }` for each `[data-block-data-layer]` element through the data layer, with stock's id assignment (an existing `id`, else `parentId` plus the index within the block's class, so the id is `<parentId>-<n>` or `<n>`) and `{}` for unparsable JSON, so the resulting `blocks` state equals the stock run's (real Chromium, stock ACDL beside).
8. **Forward to core and denylist.** With an `airlock` option, an event push is also forwarded as `airlock.push({ event, ...params })`, so other connectors and ADR-0012's denylist see it. The forward is gated like the Alloy path: nothing is forwarded before `attach()`, with `analytics: false`, or when `shouldProcessEvent` drops the event; it runs after `onEvent`, from the stored (pristine) payload, so a hook's edits do not reach it. Only `event`, `xdm` and `data` are forwarded, never `configOverrides`. Hermetic test with a real `createAirlock` and a recording connector: the connector receives the event, and a denylisted key is stripped by core's own dispatch (asserted against core's behavior at whatever depth it strips today, not a copy of the list). Double-send guard: the Alloy connector subscribes to core `page_view` (`connectors/alloy/connector.js`), so the forward skips events on a fixed list of the connector's subscriptions, pinned by a test that reads the connector's subscriptions; the test pushes `page_view` with both the forward and the Alloy path on and asserts one Alloy send. The Alloy path is not covered by the denylist today (the named wrapped-SDK gap in `contracts/push-api.md`, owned by the existing refinement-todo item); a test pins that the data layer does not claim coverage, by asserting a denylisted key in `xdm` reaches `onEvent` unchanged, so closing the gap later changes a named test, not a silent behavior.
9. **No capability.** The data layer and the proxy hold no reference to the handle or a chamber; their only output is the `onEvent` callback the library passes, which receives only mapped analytics arguments (AC4). With `dataLayer: false` the library creates none and `pushToDataLayer` throws stock's error -> 069-03 AC5 (the library does not exist yet; this slice's module has no such switch). A global-proxy test shows the module touches no global other than the proxy's one instance name (default `adobeDataLayer`, or the custom name alone). No `core/` change (the slice's diff against `core/` is empty).

**Stock-vs-airlock deviation log** (owner AC):
- Live `getState` vs ACDL's clone (AC5).
- A hook sees the state after every push so far (async drain); ACDL's listener sees per-push state (AC2/AC4).
- A throwing `shouldProcessEvent` is a `hook-threw` diagnostic; stock throws out of the page's `push` (AC4).
- Eager phase deep-merges and folds `xdm`/`data` of event items; stock shallow-merges non-event entries (AC5).
- A push with a non-string or empty `event` is dropped whole; ACDL folds the rest (AC1).
- Non-plain, accessor, Proxy, cyclic or over-deep pushes are dropped (AC2).
- `getState(path)` is dotted only, as in ACDL; ACDL's `Object.prototype` pollution is not reproduced (AC3).
- No `adobeDataLayer:*` notifications and no listeners (AC5).
- A late `push` replacement is detected at assignment, stricter than "next drain" (AC6).
- `scanBlocks` null-guards `data`; block-id collisions merge as in stock (AC7).
- A pushed Proxy's `getPrototypeOf`/`ownKeys`/`getOwnPropertyDescriptor` traps may run during one validation walk (`getOwnPropertyDescriptor` once per own key, and nested Proxies' traps too) (AC2, -> 069-04). Without `structuredClone` the backstop is absent and a Proxy whose traps return plain data is accepted (module header).
