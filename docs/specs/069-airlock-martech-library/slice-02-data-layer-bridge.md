## Slice 069-02 — the data layer without ACDL: a narrow capture bridge with Airlock's own state and event mapping

**Goal:** A site that pushes objects to `window.adobeDataLayer` keeps working with no ACDL on the page: the push is captured in O(1) on the main thread (validate and append, nothing else), Airlock's own reducer folds the state lazily when it is read or sent, and data-layer events reach the library as the same `sendAnalyticsEvent` arguments stock builds. What ACDL gave that cannot cross the airlock is diagnosed, not emulated. Why this is not core's `airlock.push` log: that log is keyed by event type for connectors and cannot carry arbitrary page state or the `event` mapping; the bridge keeps the same shape (validate, append, no interpretation) in an adapter module and does not widen `core/`.

**DoR:**
- ✅ 064-21 done (the S10 differential and the stock ACDL 3.0.1 arm exist).
- ⬜ ADR-0065 Accepted by the owner, including its Option A or B choice for where this behavior lives (this slice is written for Option A, the recommendation: a module of the library, `adapters/eds/martech-datalayer.js`, pure and dependency-free so it can move into a chamber later). If the owner picks Option B, this slice is rewritten before it is built.

**Acceptance Criteria:**

1. **Install, no ACDL.** `install({ instanceName, dataLayer })` drains the entries already in `window.adobeDataLayer` in order (object entries enqueued; function entries diagnosed, AC5), then patches `push` on the same array instance, so a reference the page took earlier keeps working. The patched `push` still appends the object to the array (so page code reading `length` or indexing keeps working), and entries are not removed; the array is bounded by the page, as with stock. A custom `instanceName` is aliased to the same array, as stock does. In the bridge page's real-Chromium test nothing requests `acdl.min.js` on the bridge side (the stock side loads real ACDL for AC3's comparison only; the journey-level no-ACDL assertion is 069-03 AC5). If a foreign ACDL is on the array at install (a `getState` and an `addEventListener` function, not ours), the bridge does not install and a `datalayer-foreign-implementation` diagnostic says so. If one loads later and takes over the array, the bridge detects the replaced `push` at the next drain, stops capturing and emits the same diagnostic, so no event is sent twice (hermetic test with a stand-in that replaces `push` and replays the array). Names `alloy` and `__alloyNS` are rejected with a plain Error (hermetic).
2. **Capture is O(1) and runs no page code.** `push(object)` validates that the argument is a plain data object (own data properties only; a `Proxy`, an accessor property or a non-plain prototype is dropped with `datalayer-bad-push`, and a cyclic or over-deep object, past a documented depth bound, is dropped the same way), appends it to the queue and returns. It does no merge and no mapping: the cost is the validation walk (bounded by the depth bound) and does not depend on the state size (hermetic: a visit counter shows the same count for a state of 10 keys and of 10,000). A non-object push never throws. Hermetic tests: a getter on a pushed object is never invoked; a `Proxy` trap is never hit; a cycle does not overflow the stack. No page function runs inside `push`: `shouldProcessEvent` and `onBeforeEventSend` are not called before `push` returns (hermetic). The drain runs in a separate task (`setTimeout(0)` or `scheduler.postTask`, not a microtask), tested with a task-boundary probe, so the page's interaction handler returns before any hook or send runs. The drain and a direct `sendEvent` keep call order (a queue shared with the library's pre-boot queue, tested).
3. **State equals ACDL's, folded lazily.** The state is folded from the queue when `getState()` is called, when `includeDataLayerState` needs it at send, or when the drain runs, and cached until the next push (a hermetic test shows `push` does not fold: the reducer's visit counter is zero after a thousand pushes). The bridge's `getState()` and `getState(path)` equal real ACDL 3.0.1's `getState()` on a corpus of pushes (nested objects, arrays, `null`, event items carrying data, the `event` and `eventInfo` keys, repeated keys), shown in real Chromium with both side by side. Every difference the corpus finds is either fixed or listed in the Findings as a dropped semantic with a diagnostic and a test of the difference. `getState` stays a synchronous main-thread read and returns the live state by reference, per `contracts/push-api.md`. The reducer copies what it stores and skips `__proto__`, `constructor` and `prototype` keys, so no push can pollute `Object.prototype` (hermetic, revert-checked). The send-time merge hands the hook a copy (`structuredClone`), so a hook that edits `payload.xdm.a.b` does not change the state (hermetic, matching stock's clone). The cost is stated honestly: `push` is O(1), and each send that includes state costs O(state size) on the main thread; the Findings record the measured cost on the S10 state.
4. **Event mapping and timing.** A push with a non-empty string `event` produces, in the drain, `onEvent({ eventType: event, ...xdm }, data, configOverrides)` exactly as `aem-martech`'s listener builds its `sendAnalyticsEvent` arguments, taking only `event`, `xdm`, `data` and `configOverrides` from the push (any other key, such as `renderDecisions`, `decisionScopes` or a consent field, is ignored; tested), without mutating the pushed payload. A push without `event` only changes state. Order is preserved. The consumer attaches when the library's lazy phase starts and only when `analytics` is true, as stock registers its listener (`martechLazy` loading ACDL): events captured before it attach are held and replayed in order at attach (stock's pending events), so no event goes out before the page view; with `analytics: false` state is kept and no event is mapped (both tested against the stock run in real Chromium). `shouldProcessEvent` returning false drops the event; one that throws drops it with a `hook-threw` diagnostic, matching what the stock run does with a throwing listener (recorded in the real-Chromium arm). A data-layer event under pending or denied consent sends nothing until the seal allows it: the bridge only calls `onEvent`, and the handle's `sendEvent` and the seal decide (069-03 AC3).
5. **Dispositions of what cannot cross, each with a diagnostic and a test.**
   - Function push (`push(function (dl) {...})`): never executed (a test asserts the function is not called); `datalayer-function-push-dropped`. Reason: it runs page code inside the capture path (`contracts/push-api.md`, AD-2).
   - `addEventListener`, `removeEventListener`, `on`, `off`: present on the bridge, register nothing, do not throw; `datalayer-listener-not-supported`. Reason: a subscribe surface needs page callbacks on the interaction path. The stock `adobeDataLayer:event` listener `aem-martech` registers is replaced by the bridge's own event mapping (AC4).
   - `adobeDataLayer:change` and `adobeDataLayer:event` notifications: not emitted (the diagnostic above covers the registration).
   - ACDL `getState` returning a deep clone: the bridge returns the live state; recorded as the stock difference, with a test that shows the live reference.
   - Stock's eager-phase fallback (a shallow merge of the non-event entries before ACDL loads, in `onBeforeEventSend`): not reproduced. The bridge merges as ACDL's `getState()` does at every phase. A test in real Chromium compares an eager-phase `sendEvent` body with the stock run's for a nested-state push; the difference (deep versus shallow, event items excluded versus included) is shown, owned here, and listed in the Findings with the diagnostic-free rationale that the stock fallback is a pre-load approximation of ACDL's own state.
   - `shouldProcessEvent` and `onBeforeEventSend`: kept on the main thread, because a function cannot cross the airlock; they run in the drain step, not in `push` (AC2).
6. **Blocks.** A `scanBlocks()` helper pushes `{ blocks: { [id]: data } }` for each `[data-block-data-layer]` element through the bridge, with stock's id assignment (an existing `id`, else the block class and its index, prefixed by `parentId`) and `{}` for unparsable JSON, so the resulting `blocks` state equals the stock run's (real Chromium, stock ACDL beside).
7. **No capability, no global beyond the data layer.** The bridge object exposes `push`, `getState` and the diagnosed stubs only, holds no reference to the handle or a chamber (its only output is the `onEvent` callback the library passes, which receives only mapped analytics arguments, AC4), and a global proxy test shows it touches only `window[instanceName]` and `window.adobeDataLayer` (never `alloy`, `__alloyNS` or `acdl`). With `dataLayer: false` nothing is installed. No `core/` change.
