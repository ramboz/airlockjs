## Proposed mutation perimeter

The owner, not the future implementer, controls product criteria, original
specs, approved reference truth, oracle plans and fragments, approval records,
review evidence and launch limits. Freeze these outside the writer's writable
workspace with an independently enforced boundary. Servo's file hashes alone
are drift detection, not an adversarial security boundary.

An eventual implementer may change approved in-scope runtime code, tests and
directly related documentation inside a separately reviewed slice. It may run
bounded local tests and synthetic controls. Do not prescribe ordinary code
edits. Case-bound, approved inputs must identify the exact reference,
environment, native cohort and authorized evidence layer. Unknown fields,
unsupported browser cohorts, unavailable response or product evidence remain
blockers. Escalate authority, evidence or architecture conflicts rather than
relaxing criteria. Stop on repeated no-progress and report the evidence and
reason; a numerical no-progress limit requires owner selection.

Implementation routes to native Copilot `gpt-6.1-terra`; each independent
review uses a fresh `gpt-6.1-sol` session. Reviewers must not share the
implementer's mutable context. SDK acquisition, new native collection, live
events, account changes, deployments, reference approval and actual endpoint
dispatch each require separate explicit grants. This packet grants none.
