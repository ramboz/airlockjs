# First-party chamber capture qualification

**Local-only qualification:** [059-16](../docs/specs/059-google-ads-full-compatibility/slice-16-chamber-capture.md)
provides an independent preparation path while live native cases await
fresh external setup facts. The fixed executable and read-only inspector
passed compliance, craft and architecture review after substantive original-
byte, publication and resource-lifetime corrections. The final source-bound
cohorts cover actual workers/receivers, real deadline failures and owned
producer-abort cleanup; checkpoint documentation reconciliation passed.
This is not native or full-replacement acceptance.

The operator path builds current first-party Airlock assets, runs the exported
EDS boots, observes actual browser module workers and serialized messages,
and captures the resulting literal-loopback HTTP exchange at an independent
receiver. It uses synthetic identifiers, explicit fixture consent and the
existing endpoint test overrides. No official vendor software development
kit (SDK), account input, public endpoint or original event slot is involved.

## What the result means

A qualified local chamber capture must link the public object-shaped push
through its actual serialized worker input, worker result and host dispatch.
An HTTP request, a page-created worker marker or a mapper unit test is not
that evidence. The fixed controls include a main-only emitter that still
reaches the same sink and an actual worker whose event delivery is dropped.
Those controls must fail the corresponding provenance checks.
The observer deliberately holds initial message delivery until its independent
worker observation attaches. Values are preserved, but this instrumented
timing is not the ordinary startup or latency baseline.

The current Meta and Google workers are **legacy subsets**, not complete tag
replacements. These fixtures do not install native `fbq` or `gtag` command
semantics, prove conversion collection, establish native-default consent,
qualify real response branches or measure adopted-page Core Web Vitals.
An instrumented synthetic capture is not a performance baseline.

| Evidence | Can establish | Cannot establish |
|---|---|---|
| Current source/build and actual loaded-asset closure | This reviewed first-party fixture did not load an unapproved dependency | Universal SDK absence in arbitrary unreviewed code, external source authenticity or account state |
| Independent real-worker and serialized-message observations | Actual chamber execution on this fixed path | Full vendor behavior or actual dispatch by themselves |
| Original browser and independent local HTTP receiver observations | This local host request/response, with actual method/type/query/header/body evidence | Ordinary native transport equivalence or a vendor backend receipt |
| External post-exit witness | Actual command disposition, final artifact digests and observed owned cleanup | Permission for a future run or producer attestation of its own future exit |

The distinct chamber producer is not a native report or the existing
comparator's `local_complete_sequence` source. Do not relabel it to pass a
native/whole-wire schema. A separately reviewed native/chamber consumer,
complete stock reference and actual replacement implementation remain open.

## Boundaries and failure handling

Only the fixed first-party fixture and pinned built graph are served.
Unknown source/target/surface, missing originals, changed pins, ambiguous
message relationships or incomplete cleanup stop qualification explicitly.
The source-control bypass uses a first-party marker, never official SDK
bytes. Native facade names are observations, not the SDK-absence test.

All work uses fresh owned contexts behind the unchanged loopback-confined
Chrome launcher and resolver denial. No source deployment, shared-site change,
system trust edit, original authority journal, Servo approval or live-window
reservation is created. Every run must close its own browser, contexts,
receiver and sockets; a producer snapshot cannot substitute for actual
post-exit observation.

The finite local limits are at most sixty seconds through build, cleanup and
publication, 64 observed requests, 2 KiB URLs, 64 KiB request headers/body,
2 MiB responses and 8 MiB aggregate original retention. Exceeding a bound is
inconclusive, not a truncated pass. Use a new private output under an
operator-owned canonical parent; never reuse or overwrite a failed directory.

## Fixed interface (qualification not yet accepted)

Use the validated Node 24 cohort and a new location under an existing
operator-owned canonical private parent. No path component may be a symlink
(on macOS, `/tmp` is an alias; use its canonical path).

```sh
PATH=/opt/homebrew/bin:$PATH node rig/chamber-capture.mjs capture \
  --output-dir /absolute/private-parent/new-chamber-capture

PATH=/opt/homebrew/bin:$PATH node rig/chamber-capture.mjs inspect \
  --output-dir /absolute/private-parent/new-chamber-capture
```

`capture` starts a fixed child, waits for actual completion, hashes its final
originals and checks registered browser processes after exit. Parent cleanup
verifies birth/image/group/user and private-profile ownership before signals,
observes bounded SIGTERM shutdown, escalates to SIGKILL when needed, and
checks process, endpoint, receiver and profile closure. It preserves the
initial left-behind and failed-producer observations separately: successful
cleanup never turns a failed producer into a qualified capture. `inspect` is
read-only: it checks source/build/dependency/browser/Node/OS identity, child
completion, raw-file hashes, actual message/source/HTTP relationships,
controls and owned cleanup. It starts no browser and grants no future action.
Changing source or cohort invalidates an old receipt rather than relabelling
it. Existing output is refused without overwriting the retained failure.

The current exact browser cohort is Chrome **155.0.8059.85**. No headless
fixture result establishes equivalence to a headed native reference.

The eight fixed browser cases comprise two actual-worker positives, matched
main-only and event-drop controls for each vendor, and a first-party
forbidden-source enforced/bypass pair. Main-only deliberately replays the
previous local positive's actual URL to the same receiver, not an independent
replacement candidate or a native reference.
Each cohort also owns a real Chrome late-acquisition control: a timed-out
pending acquisition must settle and close its actual late browser before
cleanup can be accepted. No fake browser object establishes this result.

Two additional fixed lifecycle cohorts retain an actual owned HTTP request
through a real clock boundary:

```sh
PATH=/opt/homebrew/bin:$PATH node rig/chamber-capture.mjs capture \
  --output-dir /absolute/private-parent/new-cleanup-control \
  --control cleanup-deadline

PATH=/opt/homebrew/bin:$PATH node rig/chamber-capture.mjs capture \
  --output-dir /absolute/private-parent/new-publication-control \
  --control publication-deadline
```

The corrected cutoffs are 50 seconds for cleanup and 55 seconds for report
publication, leaving time for final witness IO, inspection and actual command
completion inside the sixty-second limit. The internal producer cutoff is
57 seconds, reserving bounded parent fallback cleanup. The expired report uses the same
publisher and guard as an ordinary report. Both controls intentionally exit
**2**, even when their expected guard behavior qualifies. The publication
case retains a refusal instead of publishing a normal producer report.
Normal capture exits **0** only after the fixed local qualification passes;
invalid, failed or inconclusive execution exits **2**. Always retain the
caller's actual CLI disposition as well as the child witness.

The additional fixed `--control producer-abort` diagnostic stops a genuinely
owned Chrome and aborts its producer after registration. The parent must
observe that SIGTERM did not end it, escalate, and verify closure. The CLI
still exits **2** and the reader rejects its failed producer. The diagnostic
retains `abort-originals.json`, `abort-parent.json` and the post-child witness;
these are failure/cleanup evidence, never normal capture acceptance.

## Private evidence

The schema family is `airlock.sdk-absent-chamber-capture.v1`:

- `start.json` binds the run, fixed control and source/cohort identity.
- `capture.json` retains actual encoded originals and worker, source, HTTP,
  receiver, lifecycle and cleanup observations. The graph encoding preserves
  supported binary backing/offsets, aliases, holes and undefined values;
  unsupported structured-clone kinds stop explicitly.
- `report.json` is the producer snapshot, not a future process-exit receipt.
  The publication-expiry cohort instead retains `pre-expiry.json`.
- `publication.json` records the shared publisher's actual published/refused
  disposition, attempt/completion and deadline.
- `witness.json` binds actual child exit/signal/deadline, final artifact hashes
  and independent post-child observations of all registered browser PIDs.
  `parent_cleanup` records initial state, identity-checked signals and final
  resource observations. Its `observed_ms` is not this witness writer's future completion.
- `built/` contains the pinned outputs from the actual first-party build.

`guard_qualification: "PASS"` is **local guard qualification**, not native
acceptance. Check `case_conclusive` separately: it is false for the intended
lifecycle failures. `legacy_subset_source` and `local_only` remain true;
native, whole-wire, vendor, replacement, attribution, product and C2/C3 claims
remain false. The later qualified native/chamber consumer is still unfinished.
The reader explicitly returns `whole_cli_completion_observed: false`.
For complete command evidence the independent caller must observe actual
CLI close and retain its full elapsed time and post-exit artifact hashes.

The ordinary unit suite starts no browser. The explicit opt-in below runs
the actual normal, two deadline and producer-abort cohorts, each with its
own finite budget; the suite is not one sixty-second case. To retain originals,
set `AIRLOCK_CHAMBER_OUTPUT_PARENT` to an existing private canonical parent.
The opt-in caller saves this separate evidence in a sibling
`*-command/command.json` using `airlock.chamber-whole-cli-witness.v1`;
it is written only after the entire capture CLI and its output pipes close.
It is not a field the producer can self-certify.

```sh
AIRLOCK_CHAMBER_QUALIFICATION=1 PATH=/opt/homebrew/bin:$PATH \
  npx --no-install vitest run rig/chamber-capture.test.mjs
```
